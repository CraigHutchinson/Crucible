## Bounded shootout

| Candidate | Smallest player decision | Required rule spike | Receiving evidence |
|---|---|---|---|
| Structural reclamation | Divert a current to concentrate mass, anchor it to hold one relay, then redeploy | Eligible mass/radius, atomic insufficient-mass rejection, mobile/reserve/structure/loss accounting, protection/spread order, shatter yield, hold timer and outcome precedence | Hand-calculated conserved ledger through fuse/shatter; failed transition leaves state unchanged; owned IDs/snapshots and complete replay plan |
| Local faction arena | Direct one faction while two or more deterministic opponents contest finite stock | Stable faction/kind/controller identities, relation table, command authority, per-owner/shared stock choice, transfer/attrition/loss, contested ordering, commands for both organism kinds, elimination and simultaneous/tied outcomes | Three-plus-faction color-and-shape mock; unauthorized/stale commands reject; contested ledger and tie trace; deterministically replayable local controller schedule |

Compare both at the same bounded world/population and primitive presentation.
Record integration surfaces, total new rules, acceptance fixtures, likely player
comprehension and tool decision opportunities. Do not score either using invented
FPS, imagined playtest feedback or networking claims. Select the smallest complete
loop that uses flow decisions meaningfully; if uncertainty still changes that
selection, name a bounded executable spike and its stop criterion instead.

## Freeze checklist before implementation

- Numerical constants, capacity and resource conservation equation, including
  explicit losses and ownership transfer. Rejected commands cannot debit resources.
- Completed-tick ordering for edits, movement, reclamation, contention, structural
  transitions, spread and outcome. Specify simultaneous requests/ties explicitly.
- Stable identity/generation, removal behavior, restart, retained snapshot and trace
  ownership. Any population changes must receive Sub0ECS's actual pinned guarantees.
- Input feedback and primitive display of eligibility, ownership, depleted stock,
  contested state, losses and terminal outcomes. Preserve pause and bounded ingress.
- Independent oracle/trace, complete replay fields, actual visual examples and a
  human task sheet. Existing quota/deadline scenario remains a regression fixture.
- Inspect reuse catalog at dispatch. Keep game policy local; add no abstract renderer,
  generic multiplayer framework or upstream pin without a consumed need.

Transport, remote authority/prediction, polished materials, height/traversal and
new platform receivers are separate decisions. Local arena evidence cannot close
multiplayer, physical performance, iOS or human-comprehension gates.
